# V2: รายงานปริมาณน้ำฝน

สาขา `V2` ปรับส่วนหัวด้วยโลโก้ต้นฉบับ แสดงวันภาษาไทย ใช้หุ่นยนต์ที่ให้มา และแบ่งแผนที่เป็น 16 พื้นที่ตามภาพอ้างอิง `improve/newmap.png` ตัวเลขฝนแสดงบนพื้นที่โดยไม่มีแคปซูล แผนที่นี้เป็นพื้นที่รายงานตามภาพอ้างอิง ไม่ใช่เส้นเขตการปกครองที่รับรองทาง GIS

## ตั้งค่าพื้นหลัง

แอดมินเปิด “ตั้งค่าพื้นหลังรายงาน” เหนือภาพตัวอย่าง เลือก JPG/PNG/WebP ไม่เกิน 10 MB และ 40 ล้านพิกเซล ปรับตำแหน่งแนวนอน/แนวตั้งและความสว่าง แล้วบันทึก มีปุ่มยกเลิกตัวอย่างและคืนค่าภาพเริ่มต้น

แนะนำภาพแนวตั้ง A4 ขนาด 2480 × 3508 พิกเซล ไม่มีข้อความ/โลโก้ และมีพื้นที่ว่างด้านบนและกลางภาพ ภาพต่างสัดส่วนจะถูกครอบให้เต็มหน้า

พื้นหลังเป็นค่ากลาง: รายงานทุกวันที่เปิดหรือส่งออกใหม่ใช้ภาพล่าสุด ภาพที่ดาวน์โหลดไว้แล้วไม่เปลี่ยน ระบบระงับการดาวน์โหลดระหว่างดูตัวอย่างที่ยังไม่บันทึก

## เปิดใช้งาน Storage

1. เพิ่มค่าต่อไปนี้ใน `.env` และ Vercel Environment Variables ของ V2 (ไม่ใส่คีย์ใน Git):

   ```dotenv
   SUPABASE_URL="https://YOUR_PROJECT.supabase.co"
   SUPABASE_SECRET_KEY="YOUR_SERVER_SECRET_KEY"
   ```

   รองรับ `SUPABASE_SERVICE_ROLE_KEY` แทน secret key รุ่นใหม่ ห้ามใช้ `NEXT_PUBLIC_` กับคีย์ลับ

2. รัน `npm run db:migrate` เพิ่มตาราง ReportAppearance แบบเปิด RLS และไม่ให้ anon/authenticated เข้าถึง
3. รัน `npm run storage:setup` สร้าง bucket ส่วนตัว `report-backgrounds-v2` จำกัด 10 MB และ MIME ของรูปภาพ ไม่สร้างนโยบายให้บุคคลทั่วไปอัปโหลด
4. รัน `npm run build` และทดสอบผ่านบัญชีแอดมินบน V2 ก่อนนำขึ้น production

เบราว์เซอร์อัปโหลดตรงไป Storage ผ่าน signed URL หลังตรวจสิทธิ์แอดมิน จึงไม่ส่งไฟล์ 10 MB ผ่าน request body ของ Vercel เมื่อบันทึก เซิร์ฟเวอร์จะตรวจชนิดภาพจริง ถอดรหัสภาพ และแปลงเป็น WebP ก่อนใช้งาน ลบ metadata ของภาพต้นฉบับไปด้วย

ไฟล์ `pending/` ถูกลบหลังบันทึกสำเร็จหรือตรวจไม่ผ่าน ไฟล์ที่อัปโหลดแล้วปิดหน้า/เครือข่ายขาดก่อนบันทึกอาจค้างอยู่: ลบไฟล์ pending ที่เก่ากว่า 24 ชั่วโมงจาก Storage เป็นระยะ ภาพ `published/` เดิมเก็บไว้เพื่อไม่ให้การเปลี่ยนค่าลบภาพที่กำลังใช้อยู่จากคำขออื่น

API อ่านภาพผ่านโดเมนเดียวกับแอปเพื่อให้ PNG export ทำงานได้ ไม่ส่งคีย์ลับไปเบราว์เซอร์ ตรวจ role ล่าสุดจากฐานข้อมูลทุกครั้งที่เปลี่ยนค่าหรือขอ signed upload URL และใช้ revision ป้องกันแอดมินบันทึกทับกัน

## ตรวจสอบ

- `npm test`: เกณฑ์สีทุกจุดรอยต่อ, contrast, ค่า 0/ไม่มีข้อมูล, วันภาษาไทย, 16 พื้นที่ และค่าควบคุมพื้นหลัง
- `npm run lint` และ `npm run build`
- ตัวอย่างใน `docs/previews/v2-report-A4.png` ใช้ข้อมูลจำลองสำหรับตรวจการแสดงผล ไม่ใช่รายงานจริงของวันนั้น
- ทดสอบอัปโหลดจริง: เลือกภาพ → ตัวอย่าง → บันทึก → โหลดหน้าใหม่ → ดาวน์โหลด A4 → คืนค่าเริ่มต้น รวมทั้งบัญชี editor/viewer ต้องไม่มีสิทธิ์เปลี่ยนพื้นหลัง

หากรัน build บน Windows พร้อม dev server แล้ว Prisma รายงานว่า query engine DLL ถูกใช้งาน ให้หยุด dev server ก่อนรัน `npm run build`
